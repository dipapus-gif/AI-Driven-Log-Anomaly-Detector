From raw logs to a decision

Four stages, each one visible in the dashboard, so you can see why an alert was raised and what was done about it.

1

Ingest

Follow log files with the bundled shipper or post JSON, firewall key=value and sshd syslog lines to a token-protected endpoint.

2

Detect

Activity is grouped per source into 15-minute windows and scored against what is normal for your environment.

3

Investigate

An analyst agent pulls the evidence, checks reputation and user privileges, and tests the alert against registered jobs.

4

Respond

Confirmed threats alert your channel. Isolating a host or blocking an address needs an analyst to approve it.

What the model looks at

Basic counts miss the attacks that matter. These signals describe how traffic behaves, not just how much of it there is.

Rhythm

  • Request timing entropy Machine-regular intervals suggest C2 beaconing.
  • Packet size variance Uniform payloads stand out from human traffic.
  • Burst size Volume spikes against the source's own history.

Identity

  • Off-hours activity Measured against each user's own baseline, not a global clock.
  • Failed-login ratio Guessing, spraying and a success after many failures.
  • Privilege context Group membership from your directory.

Network

  • Rare high ports Services this environment has never used.
  • Foreign destinations Public addresses an internal host does not normally reach.
  • New subnets First contact with unfamiliar ranges.

Built so it cannot be talked into things

Logs are attacker-controlled text. The agent treats them that way.

The model suggests, code decidesActions must target addresses and hosts found in the incident itself, and policy code runs them.
Dismissals have to be earnedA false positive needs a matching registered job, or very high confidence below the isolation threshold. Malicious reputation always blocks it.
Approval before containmentAbove the threshold, isolate and block actions wait for a person. Protected hosts are always refused.
Separate accounts, safe webhooksEvery account's data is isolated. Outbound webhooks are HTTPS-only and cannot reach internal addresses.

Point it at real logs

Create an account, make an ingest token, and run the shipper on any Linux machine. Failed SSH logins from your own test attacks show up as incidents within a minute.

INGEST_TOKEN=lad_… python src/tailer.py \
  --url https://your-app/api/ingest \
  /var/log/auth.log

# or pipe any stream
journalctl -f -t sshd | python src/tailer.py \
  --url https://your-app/api/ingest -
